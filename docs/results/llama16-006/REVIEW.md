## 现有证据怎样解释差异

1. 平均 packet 延迟没有覆盖发送前的 CPU-lane 等待。后者占平均消息就绪至完成
   区间约 89%，在 Rotated 中还略有增加。因此消息级收益已经不同于 packet 均值收益。
2. 决定应用结束的两条实际关键链又不同于全部消息的平均表现。两条链的服务时间
   都约 99.95% 来自固定本地阶段；消息服务占比较小，但不能据此推导网络收益上限，
   因为消息到达还会影响资源阻塞和后续关键链选择。
3. 两条链的本地服务总量相差 2,343,646 cycles，消息服务总量相差 21,618 cycles，
   恰好合计为 2,365,264 cycles。所有同一 `calc` 的 duration 都保持原值；前一项
   表示链经过了不同的固定操作，不能解释为本地计算单元变快。这是观测记账分解，
   不能把各项当作独立干预的因果贡献。

关键消息也并非同向改善。例如，下表只取至少位于一条选定关键链的同一消息配对，
所有等待及服务时间单位均为 cycles：

| Send ID | 所属选定链 | B/R CPU 等待 | B/R 注入前等待 | B/R 注入后至完成 |
| --- | --- | ---: | ---: | ---: |
| 5075080 | Baseline | 207248 / 0 | 10770 / 921 | 2267 / 1164 |
| 2075795 | Rotated | 20118 / 278603 | 1725 / 10993 | 1303 / 1190 |

第一条消息在 Rotated 中的服务时间缩短 10,952 cycles，第二条却增长 9,155 cycles。
这帮助定位关键链变化，尚不能把最终 2.365264 ms 唯一归因于某一条消息。
注入后区间包含后续 flit 注入、传输和竞争；现有记录不足以定位具体 router/port/VC。
